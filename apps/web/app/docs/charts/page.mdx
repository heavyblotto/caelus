# Computing Charts

`engine.chart()` computes a full astrological chart from Universal Time (UT)
calendar fields, observer latitude and east-positive longitude, and either a
house-system name or a configuration object.

## Calendar fields vs. Julian Days

`engine.chart()` expects six UT calendar arguments in sequence (`year`,
`month`, `day`, `hour`, `minute`, `second`), followed by latitude and
east-positive longitude:

<CodeBlock
  lang="typescript"
  label="signature.ts"
  code={`//                         y     mo  d   h   mi  s   lat     lonEast
const chart = engine.chart(1990, 6, 10, 14, 30, 0, 27.95, -82.46, "placidus");`}
/>

Be careful not to pass a Julian Day number in the `year` argument: the engine
treats that number as a calendar year, evaluates an epoch millions of years out
of range, and throws `RangeError: jd ... outside fitted range`.

When you already have a UT Julian Day, call `engine.chartAt()` directly to
skip calendar conversion (`engine.chart()` converts calendar fields to a Julian
Day and delegates to `chartAt()`):

<CodeBlock
  lang="typescript"
  label="chart-at.ts"
  code={`const chart = engine.chartAt(jdUt, 27.95, -82.46, "placidus");`}
/>

`chartAt()` accepts the same house-system name or `ChartOptions` third argument
and returns an identical `Chart` object.

To look up a single body at a Julian Day without computing a full chart, use
`engine.position()` or `engine.longitude()`:

<CodeBlock
  lang="typescript"
  label="at-jd.ts"
  code={`engine.longitude("sun", jdUt);                        // degrees
engine.position("mars", jdUt, { zodiac: "tropical" }); // full Position`}
/>

## Options

<CodeBlock
  lang="typescript"
  label="options.ts"
  code={`const chart = engine.chart(
  1990, 6, 10, 14, 30, 0,
  27.95, -82.46,
  {
    houseSystem: "koch",
    zodiac: "sidereal:lahiri",
    bodies: ["mean_lilith"], // extra bodies beyond the core set
  },
);`}
/>

## Returned Chart structure

<CodeBlock
  lang="typescript"
  label="shape.ts"
  code={`chart.bodies.sun.lon;        // ecliptic longitude, degrees
chart.bodies.sun.speed;      // degrees per day
chart.bodies.sun.retrograde; // boolean
chart.bodies.sun.sign;       // "Gemini"
chart.bodies.sun.ra;         // right ascension (true equinox of date)

chart.angles.asc;            // ascendant
chart.angles.mc;             // midheaven
chart.cusps;                 // twelve house cusps, degrees
chart.aspects;               // [{ a, b, aspect, orb, phase, strength }, ...]
                             //   phase: applying | separating | exact
                             //   strength: 1 exact ... 0 at the orb limit
chart.houseSystem;           // the system actually used
chart.houseSystemRequested;  // what you asked for (differs on polar fallback)`}
/>

## Converting local birth times to UT

Because the core engine expects UT timestamps, convert local wall-clock birth
times first using `caelus-birth`, which resolves the IANA timezone offline from
coordinates and applies historical daylight saving rules:

<CodeBlock
  lang="typescript"
  label="birth.ts"
  code={`import { toUT } from "caelus-birth";

const t = toUT({
  year: 1990, month: 6, day: 10,
  hour: 14, minute: 30,
  lat: 27.95, lon: -82.46,
});

const chart = engine.chart(
  t.year, t.month, t.day, t.hour, t.minute, 0,
  27.95, -82.46, "placidus",
);`}
/>

<Note>
  When a local timestamp is ambiguous because clocks fell back for DST on that
  date, prompt the user to pick the earlier or later offset rather than
  guessing. <code>caelus-birth</code> returns status flags for ambiguous and
  nonexistent local times.
</Note>
