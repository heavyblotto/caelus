# Canonical Mode

Canonical mode serializes chart payloads as exact integers on a declared grid
so that identical inputs yield byte-identical JSON and SHA-256 hashes across
browsers, server runtimes, and programming languages.

Standard engine calls are already deterministic on any single machine, yet raw
IEEE-754 floating-point values carry three portability hazards that canonical
mode eliminates:

1. **Cross-runtime rounding drift.** IEEE-754 fixes basic arithmetic but leaves
   transcendental rounding (`sin`, `atan2`, etc.) to each platform's math
   library, causing 1-ulp differences across V8, JavaScriptCore, and Python's
   `libm` that break exact hashes while remaining negligible astronomically.
2. **Serialization format differences.** Floating-point string formatting varies
   across runtimes and languages, making 17-digit decimals fragile for cache
   keys or cryptographic signatures.
3. **Cusp boundary flips.** A longitude sitting within 1 ulp of a sign boundary
   or orb limit can assign a planet to a different sign, house, or aspect
   between two platforms.

## Design guarantees

- **Consistent half-up rounding.** Both TypeScript and Python round half toward
  +infinity. Ties round up consistently, placing exact boundary longitudes in
  the next sign or house and treating a quantized speed of `0` as direct.
- **Derive facts after quantization.** Zodiac sign, sign degree, house
  placement, dignities, retrograde flags, and active aspects are recomputed in
  integer arithmetic directly from quantized longitudes so numbers and derived
  facts never disagree.
- **Strict integer serialization.** The canonical JSON encoder (sorted keys, no
  insignificant whitespace) throws if any non-integer number appears, ensuring a
  canonical digest guarantees a fully quantized payload.

## Quantization grids

| Grid | Angle unit | Notes |
|---|---|---|
| `arcsec` (default) | arcseconds | `360° = 1,296,000` (fits in safe JS integers without BigInt) |
| `milliarcsec` | milliarcseconds | Finer than validated precision; intended for fine diffing |
| `centideg` | `0.01°` | Compact and easy to scan by eye |
| `dms` | `[deg, min, sec]` triples | Traditional sexagesimal integer triples |
| `accuracy` | per-body arcsec multiple | Rounds each body no finer than its validated bound (recommended for cross-platform hashing) |

Speeds share the angle grid per day, distances use micro-AU, timestamps use
integer milliseconds since J2000.0, and aspect strengths use per-mille integers.
The embedded `units` metadata inside every payload records these settings and
is hashed into the digest.

## Content digests

`chartDigest(chart, opts)` computes a SHA-256 hash over the canonical UTF-8
encoding. Matching digests indicate matching charts at the chosen grid
resolution across any runtime or language, making them safe for cache keys,
deduplication, and verification receipts. Cross-language checks confirm exact
`===` digest parity between TypeScript and Python.

<Note>
  Digest equality relies on floating-point implementations agreeing within half
  a quantization step. Because the <code>accuracy</code> grid uses step sizes
  far wider than cross-runtime float noise, it provides the most reliable
  setting for cross-platform content addressing.
</Note>

## Remainder sets

Quantization discards a sub-quantum residue on each field. Requesting a
remainder set retains those residues as integers keyed to the same payload paths
so `composeRemainders` can reconstruct a finer-grid payload exactly, and
`nearBoundary(remainders)` identifies any fields close enough to a rounding
boundary that minor float drift could flip the quantized integer and digest.

<Note>
  Because sub-quantum residues capture the exact digits where cross-runtime
  drift occurs, treat the base canonical payload as your portable contract and
  use remainder sets only down to the precision where your target runtimes
  agree.
</Note>

## Engine API

<CodeBlock
  lang="typescript"
  label="canonical.ts"
  code={`import { canonicalChart, chartDigest, canonicalChartWithRemainders,
         composeRemainders, nearBoundary } from "caelus";

const cc = canonicalChart(chart);                  // integers, arcsec grid
const id = chartDigest(chart, { grid: "accuracy" });

const { payload, remainders } = canonicalChartWithRemainders(chart);
composeRemainders(payload, remainders);            // === the finer-grid payload
nearBoundary(remainders);                          // fragility report`}
/>

Supply the same `orbs`, `aspects`, and `separation` options used when
generating `chart` so the recomputed aspect list matches your settings.

## Over MCP

`natal_chart`, `current_sky`, `returns`, and `parans` accept
`output: "canonical"` (plus `grid` for chart tools), returning the integer
payload alongside its `digest`. Pass
`remainders: "auto" | "arcsec" | "milliarcsec"` to include the precision
sidecar. See [MCP Setup](/docs/mcp).
