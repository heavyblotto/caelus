# Data Tiers

`Engine` accepts its ephemeris dataset explicitly at construction time. Two
data suppliers ship with `caelus`: the **embedded** dataset for browsers and
edge workers, and the **Node loader** for full JPL Chebyshev packs on disk.
The hosted [REST endpoint](/api/chart?lat=27.94&lon=-82.46) and{" "}
[hosted MCP server](/docs/mcp) run on the embedded dataset, while stdio
`caelus-mcp` uses the Node loader.

## Capability comparison

| Capability | Embedded (browser, edge, hosted MCP) | Node loader / stdio `caelus-mcp` | REST `/api/chart` |
| --- | :---: | :---: | :---: |
| Core bodies (Sun–Pluto, Chiron, nodes) | ✓ | ✓ | ✓ |
| Houses (12 systems), angles, aspects | ✓ | ✓ | Placidus |
| Tropical + 7 sidereal ayanamsas | ✓ | ✓ | tropical |
| Derived charts (returns, progressions, …) | ✓ | ✓ | — |
| Extended bodies (asteroids, Uranian points) | — | ✓ | — |
| Fixed stars (319-star catalog) | ✓ | ✓ | ✓ |
| Deep star field (8,920 stars to mag 6.5, opt-in) | — | ✓ | — |
| Event search (rise/set, crossings, phases, stations) | — | ✓ | — |
| Eclipses (solar, lunar) | — | ✓ | — |
| Data on disk | none (bundled) | JSON packs (precise Moon ~3.1 MB + catalogs) | none (edge) |
| Date range | 1000–3000¹ | −2998–3000³ | 1920–2080² |
| Accuracy | per body, see [Validation](/validation) | per body, see [Validation](/validation) | per body |

<Note>
  ¹ Planets, Pluto, and the Moon validate across 1000–3000 CE; small bodies
  (asteroids and Chiron) span 1600–2484 CE, the widest window JPL Horizons
  serves. While the embedded dataset calculates any feature derived from the
  core bodies (including derived charts, sidereal shifts, eclipses, and event
  searches), the Node loader supplies the higher-precision Moon pack and
  extended body catalogs. See <a href="/docs/edge-cases">Edge Cases &amp; Stability</a>{" "}
  for out-of-range and missing-pack behavior.
  ² The hosted REST demo accepts only the embedded Moon tier (1920–2080). Hosted{" "}
  <code>/api/mcp</code> uses the same embedded dataset, whereas stdio{" "}
  <code>caelus-mcp</code> matches the Node-loader column.
  ³ Classical era packs extend the Sun, Moon, Mercury, Venus, Mars, Jupiter, and
  Saturn from 3000 BCE back to 1000 CE, joining continuously with each modern
  pack at 1000 CE and verified against held-out JPL Horizons epochs. Uranus,
  Neptune, Pluto, Chiron, and small bodies have no classical packs and appear in{" "}
  <code>chart.unavailable</code> before their fitted spans begin.
</Note>

## Embedded dataset (browser and edge)

`caelus/data-embedded` bundles a self-contained dataset covering the eight
planets, the Moon, Pluto, Chiron, the lunar nodes, and the 319-star HYG
fixed-star catalog (~13 KB gzipped out of the ~153 KB total dataset), enabling
all 12 house systems and aspects in browser and edge environments with no disk
access:

<CodeBlock
  lang="typescript"
  label="embedded.ts"
  code={`import { Engine } from "caelus";
import { embeddedData } from "caelus/data-embedded";

const engine = new Engine(embeddedData);`}
/>

## Node loader (full packs on disk)

`loadNodeData` reads the full ephemeris packs from disk: JPL Horizons DE441
Chebyshev packs for every planet, Earth, Pluto, the Moon, Chiron, and major
asteroids, replacing the compact embedded VSOP87D and analytic series wherever
present. Those modern packs establish the validated 1000–3000 CE range
(1600–2484 CE for small bodies). `loadNodeData` also discovers **era packs**
(`{body}_cheb.classical.json`) stored beside each modern pack, extending the
seven classical bodies (Sun via Earth's pack, Moon, Mercury, Venus, Mars,
Jupiter, Saturn) back to 3000 BCE and switching cleanly across the 1000 CE
boundary. Uranian points and fixed-star catalogs ship on disk as well; use
the Node tier whenever you need extended bodies, classical-era dates, or
maximum lunar accuracy.

<CodeBlock
  lang="typescript"
  label="node.ts"
  code={`import { Engine } from "caelus";
import { loadNodeData } from "caelus/node";

// The directory that holds the packs: the data folder of the installed package.
const engine = new Engine(loadNodeData("node_modules/caelus/data"));
const star = engine.fixedStar("Aldebaran", jd);`}
/>

<Note>
  If an optional pack file is missing on disk, <code>loadNodeData</code> falls
  back per body to the embedded dataset rather than throwing. Data packs are
  versioned build artifacts with recorded <a href="/provenance">provenance</a>.
</Note>

## Turbo tier (bulk longitude scans)

For multi-century sweeps that evaluate planetary longitudes tens of thousands of
times (such as long transit or return scans), `Turbo` trades full chart fields
for lookup speed. A turbo pack stores a segmented Chebyshev fit of the engine's
apparent longitudes for a chosen body list and span, reducing each evaluation to
a short polynomial pass with zero I/O:

<CodeBlock
  lang="typescript"
  label="turbo.ts"
  code={`import { Turbo } from "caelus";

// pack: a TurboPack you minted for your range/bodies (python/fit_turbo.py).
const turbo = new Turbo(pack);
turbo.has("mars");            // is this body in the pack?
turbo.longitude("mars", jd);  // apparent longitude (degrees), within [jd0, jd1]`}
/>

<Note>
  <code>Turbo</code> returns longitude only, without latitude, distance,
  houses, or aspects. Use it to filter candidate timestamps quickly, then call{" "}
  <code>Engine</code> for full charts at those timestamps. Queries outside a
  pack&apos;s fitted range throw an error.
</Note>

## Bundle sizes

Because `caelus` tree-shakes unused features (a chart-only import excludes event
search, eclipses, `when()`, turbo packs, and derived modules), client bundle
size depends mainly on whether you include the embedded dataset:

| Package or asset | Approx. gzipped | Notes |
| --- | :---: | --- |
| Embedded dataset (`caelus/data-embedded`) | ~153 KB | planets, Moon series, Pluto, Chiron, nutation, fixed-star catalog; full client-side charts |
| Precise Moon tier (`caelus/node`) | ~750 KB | ~1.7 MB on disk; lazy-loaded on demand, excluded from client bundles |
| `caelus-wheel` | ~3 KB | React is a peer dependency and is not bundled |
| `caelus-birth` | small code + IANA timezone data | weight comes primarily from offline timezone data |
| `caelus-mcp` | server-side | not intended for browser bundles |

Bundle `caelus` plus `caelus/data-embedded` when you need zero-latency charts in
the browser, or run charts server-side behind the{" "}
[REST endpoint](/api/chart?lat=27.94&lon=-82.46) or [MCP server](/docs/mcp)
and ship only `caelus-wheel` to render SVGs on the client.

<Note>
  Exact minified, gzipped, and brotli sizes come from{" "}
  <code>npm run bundle-sizes</code> via esbuild. Re-run it after changing public
  exports; the figures above reflect coefficient assets, which do not
  tree-shake further.
</Note>
