# Chart provenance

Calling `chartAt(jd, lat, lon)` assumes a verified historical timestamp and
geographic location. Many valid charts do not fit that mold: future forecasts,
fictional characters, pure archetypes, counterfactual timelines, approximate birth
hours, or narrative calendars such as Stardates or regnal years.

The provenance layer captures both what a chart represents (`Realm`) and how
precisely its time and coordinates are known (`TemporalAnchor` and
`SpatialAnchor`). Rather than calculating positions directly, it resolves
anchors to concrete inputs (or explains why none can be resolved), routes
generation to either ephemeris lookup or constraint compilation, and passes
`realm` and `certainty` metadata into the
[interpretation layer](/docs/interpretation).

```text
AnchoredChart { realm, when, where?, constraints? }
  → resolveTime / resolvePlace (Certainty: exact | approximate | representative | none)
  → realize(): ephemeris (chartAt) | compiler (compileForm) | none
  → interpretationContext(chart, { provenance: { realm, certainty } })
```

## Chart realms

| Realm | Meaning | Typical generator |
|---|---|---|
| `observed` | Verified firsthand | ephemeris |
| `reported` | Recorded secondhand (such as a quoted birth time) | ephemeris |
| `planned` | Real future timestamp chosen intentionally | ephemeris |
| `forecast` | Future moment estimated by model or range midpoint | ephemeris |
| `fictional` | Character or event in an invented setting | ephemeris or compiler |
| `mythic` | Deity, legend, or sacred narrative | ephemeris or compiler |
| `counterfactual` | Perturbed real event (e.g., an hour earlier) | ephemeris |
| `archetypal` | Purely symbolic structure (e.g., "the chart of Aries") | compiler (constraints) |
| `conceptual` | Idea, organization, or abstract entity | compiler (constraints) |

`isTimeAnchored(realm)` splits the default path: real-time realms resolve a
timestamp and evaluate the ephemeris, while `archetypal` and `conceptual`
realms generally pass geometric `constraints` to the compiler. `counterfactual`
bridges both by starting from a real timestamp and perturbing it.

## Temporal and spatial anchors

`TemporalAnchor` models timestamps across varying levels of precision, with
`relative` and `narrative` variants acting as lightweight constraint links:

| kind | Resolves to | Certainty |
|---|---|---|
| `instant` | Parsed UT Julian Day | `exact` |
| `range` | Midpoint JD with outer bounds retained | `representative` |
| `relative` | Reference registry timestamp plus parsed offset | `approximate` |
| `narrative` | Output of a pluggable custom calendar resolver | `approximate` |
| `symbolic` / `none` | `null` (preserving the rationale or missing reason) | `none` |

Relative offsets accept shorthand durations (`"3d"`, `"-2h"`, `"6mo"`) or
ISO-8601 durations (`"P1Y2M10DT2H30M"`), using mean calendar lengths for months
and years.

`SpatialAnchor` provides parallel coverage (`geo`, `named`, `region`, `relative`,
`fictional`, and `none`). `resolvePlace` checks the `AnchorRegistry` gazetteer
for `named` locations and stored coordinates for `relative` anchors. Using
`none` produces a chart with positions only and no angles or house cusps.

## Anchor registry

`AnchorRegistry` supplies domain lookups required by `relative`, `narrative`,
and `named` anchors:

- **`instants`**: maps `anchorId` strings to UT Julian Days.
- **`calendars`**: maps calendar names to `(value) => jd | null` resolvers.
- **`places` / `gazetteer`**: resolves named or relative geographic coordinates.

If a requested entry is missing from the registry, resolution returns `null`
with an explanatory note instead of fabricating a timestamp or coordinate:

<CodeBlock
  lang="typescript"
  label="resolve.ts"
  code={`import { resolveTime, resolvePlace, parseOffset } from "caelus";

const reg = {
  instants: { ev: 2110700.5 },
  calendars: {
    stardate: (v) => v === "41153.7" ? 2451545.0 : null,
  },
};

// Exact instant
resolveTime({ kind: "instant", utc: "1990-06-10T14:30:00Z" });
// → { jd, certainty: "exact" }

// Forecast window: midpoint, representative certainty
resolveTime({
  kind: "range", earliest: "2030-01-01", latest: "2030-12-31",
});

// Three days after a known event
parseOffset("3d"); // days
resolveTime(
  { kind: "relative", relation: "after", anchorId: "ev", offset: "P3D" },
  reg,
);`}
/>

## Routing with `realize()`

`realize(engine, anchored, registry, opts)` connects anchor resolution to the
engine's two chart-generation paths:

1. **Ephemeris (`via: "ephemeris"`)**: when a valid UT Julian Day resolves,
   evaluates `chartAt` and attaches `realm` metadata for downstream prose.
2. **Compiler (`via: "compiler"`)**: when no timestamp resolves and
   `constraints` are supplied, invokes `compileForm` to synthesize matching
   planetary positions.
3. **Unresolved (`via: "none"`)**: when neither succeeds, returns a diagnostic
   `note` explaining why resolution failed.

Whenever a valid timestamp resolves alongside constraints, the ephemeris path
takes precedence:

<CodeBlock
  lang="typescript"
  label="realize.ts"
  code={`import { Engine, realize, julianDay } from "caelus";
import { embeddedData } from "caelus/data-embedded";

const engine = new Engine(embeddedData);

// Observed birth: ephemeris
const birth = realize(engine, {
  realm: "observed",
  when: { kind: "instant", utc: "1990-06-10T14:30:00Z" },
  where: { kind: "geo", lat: 27.95, lonEast: -82.46 },
});
// birth.via === "ephemeris"; birth.chart is the Chart

// Archetypal symbol: compiler
const aries = realize(engine, {
  realm: "archetypal",
  when: { kind: "symbolic", rationale: "the sign Aries" },
  constraints: [
    { kind: "sign", body: "sun", sign: 0 },
    { kind: "aspect", a: "sun", b: "moon", angle: 120 },
  ],
});
// aries.via === "compiler"; aries.form holds the synthesized form

// Forecast range: ephemeris at the representative midpoint
const outlook = realize(engine, {
  realm: "forecast",
  when: { kind: "range", earliest: "2030-01-01", latest: "2030-12-31" },
});
// outlook.time.certainty === "representative"`}
/>

## Damping and framing in interpretations

Forward `realm` and `certainty` from `realize()` into `interpretationContext` so
salience weights and LLM framing reflect how reliably the chart's time is known:

<CodeBlock
  lang="typescript"
  label="framing.ts"
  code={`import { interpretationContext, chartBrief } from "caelus";

const realized = /* ... realize() above ... */;
if (!realized.chart) throw new Error(realized.note);

const ctx = interpretationContext(realized.chart, {
  provenance: {
    realm: realized.realm,
    certainty: realized.time.certainty,
  },
});

const brief = chartBrief(ctx, { limit: 24 });
// brief.prompt prepends realmFraming when needed:
//   forecast → provisional language
//   mythic → symbol, not biography
//   representative time → distrust Moon, angles, houses`}
/>

Whenever `certainty` is weaker than `exact`, time-sensitive atoms (Moon
positions moving ~13°/day and angles moving ~15°/hr) have their salience scaled
by `0.7` (`approximate`) or `0.6` (`representative`), while slow-moving
planets keep full weight. Readings on imprecise charts naturally emphasize
durable sign and outer-planet placements.

See the [Interpretation guide](/docs/interpretation) for full details on fact
atoms, selectors, rule corpora, and citation audits.

## Choosing the right entry point

- **Known timestamp and location** (`observed`, `reported`): call `chartAt`
  directly, or `realize` to keep certainty metadata attached.
- **Electional or forecast window** (`planned`, `forecast`): use a `range`
  anchor and evaluate at `representative` certainty.
- **Fiction, myth, or archetype** (`fictional`, `mythic`, `archetypal`): tag
  the `realm` explicitly and supply `constraints` when no real timestamp exists.
- **Counterfactual exploration** (`counterfactual`): combine a `relative`
  time anchor with a reference event, or use `counterfactual()` and
  `chartDiff()` (MCP: `counterfactual_chart`) to perturb time, coordinates, or
  body longitudes and inspect resulting sign, house, and aspect changes.
- **Narrative calendars** (`narrative`): register a custom converter in
  `AnchorRegistry.calendars`.
- **No geographic location** (`where: { kind: "none" }`): calculates body
  positions without house cusps or angles.
