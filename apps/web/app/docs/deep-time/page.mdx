# Deep time

The engine's default data is validated from 1000 to 3000 CE. Era packs carry
ten bodies back to 3000 BCE, and they load in Node. A date that old also
needs a calendar, a model of the Earth's rotation, and a way to say which
bodies are missing. This guide covers all four.

```ts
import {
  Engine, julianDay, calendarDate, deltaT, deltaTSigma,
  engineCapabilities, chartStability, solarEclipses,
} from "caelus";
import { loadNodeData } from "caelus/node";

const engine = new Engine(loadNodeData("node_modules/caelus/data"));
```

## What the era packs cover

An era pack is a Chebyshev fit to JPL Horizons (DE441) for one body from
3000 BCE to 1000 CE. It sits beside the body's modern pack as
`{body}_cheb.classical.json` and ends at the instant the modern pack begins,
so the two read as one span. Ten bodies have one: the Sun (through the
Earth's pack), the Moon, and the planets from Mercury to Pluto.

`engineCapabilities` reports what a given engine can compute. Each entry in
`bodies` names the body's `source`, its `validated` span, and the `fitted`
span of its packs, in astronomical years.

```ts
engineCapabilities(engine).bodies.find((b) => b.body === "saturn");
// { body: "saturn", source: "chebyshev_pack",
//   validated: { from: -3003, to: 3000 }, fitted: { from: -3003, to: 3001 } }
```

| Body | Embedded tier, `validated` | Node loader, `validated` |
|---|---|---|
| Sun, Moon, Mercury, Venus, Mars | 1000 to 3000 | −2998 to 3000 |
| Jupiter | 1000 to 3000 | −3000 to 3000 |
| Saturn | 1000 to 3000 | −3003 to 3000 |
| Uranus, Neptune | 1000 to 3000 | −2999 to 3000 |
| Pluto | 1885 to 2099 | −2999 to 3000 |
| Chiron | 1600 to 2484 | 1600 to 2484 |

Astronomical years count a year zero, so −2998 is 2999 BCE. Jupiter and
Saturn start a few years earlier because their packs are cut in longer
segments, and each pack is a whole number of segments ending where the modern
pack begins.

Each era pack records its worst error against the Horizons samples it was
fitted from, as a distance:

```ts
engine.data.eraPacks.saturn[0].provenance.true_error_au;   // 0.0000057
```

| Era pack | Recorded error |
|---|---|
| Mercury | 3.3e-6 AU |
| Venus | 3.1e-7 AU |
| Mars | 2.9e-8 AU |
| Jupiter | 2.8e-6 AU |
| Saturn | 5.7e-6 AU |
| Uranus, Neptune, Pluto | 8.2e-7 AU each |
| Earth (the Sun) | 5.7e-6 AU |
| Moon | 7.9 km |

## Embedded and Node

`loadNodeData` takes the directory that holds the packs, which is the `data`
folder of the installed `caelus` package. It loads the Horizons packs for the
planets, the Earth, Pluto, and the Moon, the era packs beside them, and the
asteroids, Uranian points, and star catalogs. The embedded tier in
`caelus/data-embedded` carries compact series in their place and no era pack.

The embedded tier does not refuse an ancient date. It computes from its series
and attaches an `outside_validated_range` warning for the Sun, the Moon, and
each planet, because nothing before 1000 CE was measured for it. For 24 January 76 CE the two
tiers disagree by 47″ on the Moon, 40″ on Saturn, 13″ on Jupiter, and 5″ or
less on the Sun, Mercury, Venus, and Mars.

The hosted MCP endpoint uses the embedded tier, and a page in a browser
starts on it. A local `caelus-mcp` uses the Node loader.

## The full packs in a browser

A browser bundle carries the embedded tier. The full packs are 27.4 MB in 17
files, too much to bundle, and a page can fetch the ones it needs.
`loadPacks` takes a manifest of the packs a site publishes and a function
that fetches one file, and returns engine data with those packs placed over a
base.

```ts
import { Engine, loadPacks, selectPacks } from "caelus";
import { embeddedData } from "caelus/data-embedded";

const base = "/data/packs/";
const manifest = await (await fetch(base + "manifest.json")).json();
const packs = selectPacks(manifest, {
  bodies: ["saturn", "jupiter", "mars", "venus"], fromYear: -800, toYear: 0,
});
const data = await loadPacks(embeddedData, manifest, packs,
  async (file) => (await fetch(base + file)).arrayBuffer());

const engine = new Engine(data);
```

`selectPacks` picks what a computation needs: the packs of the bodies named,
the Earth's for the Sun and for every planet, and only the eras the years
touch. A planet needs the Earth because its position in the sky is the
difference of the two; with Saturn's pack alone, the Earth would still come
from the embedded series. The call above selects five files, 4.2 MB. All
seven classical bodies across both eras are 14 files, 27.2 MB.

The manifest lists each file's size and SHA-256. The loader checks both
before it decodes a pack, and it rejects with a `PackIntegrityError` if one
bit differs. It fetches only the files it is handed, and only ones the
manifest lists.

An engine built this way gives the positions an engine on `loadNodeData`
gives, because both decode the same files into the same fields. The loader's
test compares 28 positions with `===`, at four instants from 2500 BCE to 1990.
The loader runs in browsers, in Node, and in a Cloudflare Worker. It needs Web
Crypto, which a browser provides on HTTPS and on `localhost`.

Decoded packs take memory. With all 14 files loaded, one Chromium tab held
about 135 MB more than before.

This site publishes its packs at `/data/packs/`, and the
[Sky Dating instrument](/instruments/sky-dating) loads them when its Data
control is set to the full packs. The format and the publishing step are in
[`docs/binary-packs.md`](https://github.com/heavyblotto/caelus/blob/main/docs/binary-packs.md).

## A chart in 76 CE

```ts
const jd = julianDay(76, 1, 24, 6, 0, 0, "julian");
const chart = engine.chartAt(jd, 41.9, 12.5, "whole_sign");   // Rome

chart.unavailable;   // ["chiron"]
```

| Body | Longitude |
|---|---|
| Sun | 2°41′ Aquarius |
| Moon | 27°16′ Capricorn |
| Mercury | 6°54′ Capricorn |
| Venus | 14°01′ Pisces |
| Mars | 19°13′ Pisces |
| Jupiter | 26°33′ Capricorn |
| Saturn | 29°57′ Sagittarius |
| Uranus | 23°41′ Aquarius |
| Neptune | 2°00′ Taurus |
| Pluto | 19°03′ Aquarius |

The Ascendant is 20°26′ Capricorn. The date is the one the
[Sky Dating](/docs/sky-dating) guide recovers from seven sign positions.

`chart.unavailable` lists the bodies whose packs do not reach the instant.
They are left out of `chart.bodies` instead of being computed from data that
was never fitted there, so code that reads a body should check for it first.
`engine.position("chiron", jd)` throws a `RangeError` for the same reason.

## Julian calendar dates

Historical dates before 15 October 1582 are written in the Julian calendar.
`julianDay` reads its date as Gregorian unless the seventh argument says
otherwise, and `calendarDate` converts back in either calendar.

```ts
julianDay(76, 1, 24, 6, 0, 0, "julian");   // 1748839.75
julianDay(76, 1, 24, 6, 0, 0);             // 1748841.75, two days later

calendarDate(1748839.75, "julian");   // { year: 76, month: 1, day: 24, hour: 6 }
calendarDate(1748839.75);             // { year: 76, month: 1, day: 22, hour: 6 }
```

The two calendars are two days apart in the first century and ten days apart
at the reform: 4 October 1582 in the Julian calendar is Julian Day 2299159.5,
and 15 October 1582 in the Gregorian is 2299160.5, the next day.

Years are astronomical here too. The total solar eclipse of 28 May 585 BCE is
in year −584:

```ts
const [eclipse] = solarEclipses(engine,
  julianDay(-584, 5, 1, 0, 0, 0, "julian"), julianDay(-584, 6, 30, 0, 0, 0, "julian"));

eclipse.type;                           // "total"
calendarDate(eclipse.tMax, "julian");   // 28 May, hour 14.44, which is 14:26 UT
```

## ΔT

The packs are computed on a uniform timescale, Terrestrial Time. A date and
clock time are in Universal Time, which follows the rotation of the Earth,
and the rotation is slowing unevenly. ΔT is the difference between the two.
The engine applies it to every instant, and `deltaT` returns it in seconds.

The model joins published sources in order. From 1955 to 2025 it uses the
values the IERS observed, and from 1948 to 1955 the Espenak and Meeus polynomial. From −720
to 1948 it uses the spline of Morrison, Stephenson, Hohenkerk, and Zawilski
(2021), which is fitted to historical eclipse and occultation records. Before
−1520 it uses the same authors' long-term parabola, and from −1520 to −720 a
Hermite curve joins the parabola to the spline. That join is this engine's
construction and is not part of the published table. After 2025 the value is
an extrapolation.

`deltaTSigma` returns the one-sigma uncertainty of ΔT for a year. Before 1700
it is the larger of two published numbers: the standard error tabulated with
Stephenson, Morrison, and Hohenkerk's 2016 values, and the amount by which
the authors' 2020 revision moved the value at that epoch. Around 1000 CE the
revision moved ΔT by 180 seconds where the 2016 table stated 15, so the
revision sets the figure there. Before −720 the published values are
extrapolations, and before −2000 the engine extends the table at its slope.

```ts
deltaT(julianDay(76, 1, 1, 0, 0, 0, "julian"));   // 9647.4
deltaTSigma(76);                                  // 148.8
```

| Year | ΔT (s) | Sigma (s) | Angles | Moon |
|---|---|---|---|---|
| −2998 | 75,278 | 3,598 | 14.99° | 32.98′ |
| −1000 | 25,310 | 1,440 | 6.00° | 13.20′ |
| −500 | 16,939 | 150 | 0.62° | 1.38′ |
| 0 | 10,441 | 129 | 0.54° | 1.18′ |
| 500 | 5,586 | 40 | 0.17° | 0.37′ |
| 1000 | 1,650 | 180 | 0.75° | 1.65′ |
| 1600 | 109 | 19 | 0.08° | 0.17′ |
| 1800 | 18 | 1 | 0.00° | 0.01′ |
| 2000 | 64 | 0.06 | 0.00° | 0.00′ |

Each row is the first day of its year. The last two columns turn sigma into
position. The Ascendant and Midheaven
rotate 0.25° for each minute of clock error, and the Moon moves 0.55″ each
second. In 2999 BCE the correction itself is 20.9 hours, and it is known to
about eleven minutes.

## What the warning means

A chart computed for an epoch where sigma is 10 seconds or more carries a
`delta_t_uncertain` warning. That covers every year up to 1666, and it
returns from 2137 as the extrapolation widens.

```ts
chart.warnings;
// [{ kind: "delta_t_uncertain", sigmaSeconds: 245,
//    angleSmearDeg: 1.02, moonSmearArcmin: 2.24, text: "..." }]
```

For the 76 CE chart, the clock time maps to an instant on the uniform
timescale that is uncertain by about four minutes. The Ascendant and
Midheaven are good to about a degree and the Moon to about two arcminutes.
The planets move too slowly for four minutes to show.

Whether that matters depends on the question. `chartStability` answers it
fact by fact, and with no window given it uses the ΔT sigma of the epoch:

```ts
chartStability(engine, jd, { lat: 41.9, lonEast: 12.5 }).summary;
// { facts: 31, stable: 31 }
```

Every fact of this chart holds across the uncertainty: each sign, house,
aspect, and direction of motion, the sect, and the sign on each angle.
[Uncertain Times](/docs/uncertain-time) covers the function, and
[Sky Dating](/docs/sky-dating) covers searching for a date when the time is
the unknown.

## Limits

- Chiron and the asteroids have no era pack, because Horizons serves small
  bodies only from about 1600. They are unavailable before then.
- The accuracy table publishes arcsecond bounds for 1000 to 3000 and none yet
  for the era packs. The recorded fit errors above are the measurement that
  exists. The modern figures are on [Validation](/validation).
- Sigma before −2000 is an extrapolation of the published table, which
  stops there. At 3000 BCE it is an hour, which is 15° on the angles: a chart
  that far back fixes the planets and leaves the houses open.
- The era packs ship in the npm tarball as binary files and are about 16 MB
  of it. A browser bundle does not include them. A page fetches the ones it
  needs with `loadPacks`.
