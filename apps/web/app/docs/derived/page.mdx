# Derived Charts

The derived layer computes standard secondary astrological techniques on top of
Caelus's validated positions. Because these functions apply time mappings or
arithmetic transforms to Swiss Ephemeris-validated coordinates, they require no
extra ephemeris tables. All TypeScript implementations match the Python
reference suite through cross-language golden tests and export directly from
the `caelus` package root.

<Note>
  Every derived helper accepts an <code>Engine</code> instance and UT Julian
  Days (use <code>julianDay()</code> to convert calendar dates). Instantiate
  <code>Engine</code> once at module scope and reuse it across calls.
</Note>

<CodeBlock
  lang="typescript"
  label="setup.ts"
  code={`import { Engine, julianDay } from "caelus";
import { embeddedData } from "caelus/data-embedded";

const engine = new Engine(embeddedData);

const natalJd = julianDay(1990, 6, 10, 14, 30, 0);   // UT
const targetJd = julianDay(2026, 6, 13, 0, 0, 0);`}
/>

## Returns

A return occurs when a transiting planet reaches its exact natal ecliptic
longitude. Because outer planets can cross the same degree up to three times
around a retrograde station, return helpers return an array of every crossing
within the requested search window:

<CodeBlock
  lang="typescript"
  label="returns.ts"
  code={`import { solarReturn, lunarReturn, returns } from "caelus";

// Next solar return after the 2026 birthday window:
solarReturn(engine, natalJd, targetJd, targetJd + 366);   // [jd, ...]
lunarReturn(engine, natalJd, targetJd, targetJd + 30);

// Any body, e.g. the Saturn return:
returns(engine, "saturn", natalJd, natalJd, natalJd + 365 * 30);`}
/>

## Secondary progressions and solar arc

Secondary progressions map one ephemeris day of planetary motion after birth to
one year of life (`progressedJd`), while `solarArc` measures how far the
progressed Sun has advanced and applies that offset to any natal body via
`directedLongitude`:

<CodeBlock
  lang="typescript"
  label="progressions.ts"
  code={`import { progressedLongitude, solarArc, directedLongitude } from "caelus";

progressedLongitude(engine, "moon", natalJd, targetJd);   // progressed Moon
solarArc(engine, natalJd, targetJd);                      // arc in degrees
directedLongitude(engine, "mars", natalJd, targetJd);     // solar-arc directed Mars`}
/>

## Composite and Davison charts

A composite chart computes the shorter-arc midpoint between each pair of natal
longitudes. A Davison relationship chart casts an actual chart at the
midpoint in time and geographic coordinates: `davisonParams` computes the
midpoint timestamp, latitude, and longitude so you can look up real
planetary positions and house cusps at that point:

<CodeBlock
  lang="typescript"
  label="relationship.ts"
  code={`import { compositeLongitudes, davisonParams } from "caelus";

const bodies = ["sun", "moon", "mercury", "venus", "mars"];
const jdB = julianDay(1988, 2, 2, 9, 15, 0);

compositeLongitudes(engine, natalJd, jdB, bodies);   // { sun: 123.4, ... }

// Davison: the midpoint in time and place, then real positions there.
const [midJd, midLat, midLon] = davisonParams(
  natalJd, jdB, 27.95, -82.46, 40.71, -74.01,
);
engine.longitude("sun", midJd);    // Davison Sun longitude (degrees)
engine.position("venus", midJd);   // full position at midLat/midLon`}
/>

## Harmonics and antiscia

An `n`th-harmonic chart multiplies each ecliptic longitude by `n` modulo 360°.
Antiscia mirror points symmetrically across the solstice axis (0° Cancer / 0°
Capricorn) or the equinox axis (0° Aries / 0° Libra):

<CodeBlock
  lang="typescript"
  label="harmonics.ts"
  code={`import { harmonicChart, antiscion, contraAntiscion } from "caelus";

harmonicChart(engine, natalJd, ["sun", "moon", "venus"], 5);   // 5th harmonic

antiscion(15);        // reflection across 0° Cancer / 0° Capricorn
contraAntiscion(15);  // reflection across 0° Aries / 0° Libra`}
/>

## Draconic charts

A draconic chart shifts zero degrees to the Moon's ascending node by
subtracting the node's longitude from every planet, house cusp, and angle
(modulo 360°), leaving declinations unchanged. It defaults to the true node
(pass `"mean"` to use the mean node); because any ayanamsa shifts both bodies
and node equally, draconic longitudes are invariant across tropical and sidereal
zodiacs:

<CodeBlock
  lang="typescript"
  label="draconic.ts"
  code={`import { draconicChart, draconicLongitude } from "caelus";

const d = draconicChart(engine, natalJd, undefined, "true", 27.95, -82.46);
// d.bodies.sun, d.bodies.moon, ... in draconic degrees; d.angles when lat/lon given

draconicLongitude(engine.longitude("venus", natalJd), d.node_lon);`}
/>

## Declination aspects and out-of-bounds planets

Parallels (same declination sign) and contraparallels (opposite declination
sign) match bodies within an angular declination orb. A body is considered
out of bounds when its absolute declination exceeds Earth's true obliquity of
the ecliptic:

<CodeBlock
  lang="typescript"
  label="declination.ts"
  code={`import { declinationAspects, outOfBounds, outOfBoundsMargin } from "caelus";

declinationAspects(engine, ["sun", "moon", "mars"], natalJd);
// [{ a: "sun", b: "mars", kind: "parallel" }, ...]

outOfBounds(engine, "moon", natalJd);        // true | false
outOfBoundsMargin(engine, "moon", natalJd);  // degrees past the obliquity`}
/>

## Essential dignities and sect

Essential dignities classify a planet in a sign as `domicile`, `exaltation`,
`detriment`, or `fall`. Sect divides charts into diurnal (`"day"`, Sun above
the horizon) and nocturnal (`"night"`) to indicate whether each planet occupies
its preferred hemisphere and sect:

<CodeBlock
  lang="typescript"
  label="dignities.ts"
  code={`import { dignityOf, isDayChart, inSect } from "caelus";

dignityOf(engine, "mars", natalJd);   // ["domicile"] in Aries/Scorpio, etc.

const day = isDayChart(engine, natalJd, 27.95, -82.46);
inSect("jupiter", day);   // true when Jupiter is in sect (diurnal by day)`}
/>

For traditional five-fold essential dignity scoring, `dignityScore` applies
William Lilly's point weights (rulership +5, exaltation +4, triplicity +3, term
+2, face +1; detriment −5, fall −4) and returns each component alongside the
net `total` and `peregrine` flag. `almuten` identifies the highest-scoring
planet at a given degree. All triplicity (Dorothean), term (Egyptian bounds),
and face tables document their classical source:

<CodeBlock
  lang="typescript"
  label="dignity-score.ts"
  code={`import { dignityScore, almuten } from "caelus";

dignityScore("mars", 5, "night");   // Mars at 5° Aries, night chart
// { rulership: 5, triplicity: 3, term: 0, ... total: 8, peregrine: false }

almuten(5);   // { planet: "mars", score: 8 }, strongest at that degree`}
/>

## Building timelines

Derived helpers compose naturally into multi-year timelines: return scans
already return arrays across `[start, end]`, while progression helpers are pure
functions of any target Julian Day. Convert any returned Julian Day directly to
a UTC calendar string with the standard JavaScript epoch offset:

<CodeBlock
  lang="typescript"
  label="timelines.ts"
  code={`import { solarReturn, progressedLongitude } from "caelus";

const SIGNS = ["Aries", "Taurus", "Gemini", "Cancer", "Leo", "Virgo",
  "Libra", "Scorpio", "Sagittarius", "Capricorn", "Aquarius", "Pisces"];
const toDate = (jd: number) =>
  new Date((jd - 2440587.5) * 86400000).toISOString().slice(0, 10);

// A decade of solar returns:
const from = julianDay(2026, 1, 1, 0, 0, 0);
solarReturn(engine, natalJd, from, from + 365.25 * 10).map(toDate);
// ["2026-06-10", "2027-06-11", ...]
//
// rendered below from this exact call:

// Progressed-Moon sign at each birthday for the next twelve years:
for (let year = 2026; year < 2038; year++) {
  const jd = julianDay(year, 6, 10, 0, 0, 0);
  const lon = progressedLongitude(engine, "moon", natalJd, jd);
  console.log(year, SIGNS[Math.floor(lon / 30)]);
}`}
/>
