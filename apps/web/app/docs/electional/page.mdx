# Electional search

Electional astrology works in the reverse direction of a natal chart: rather
than computing positions for a fixed birth timestamp, you search across a time
window to find the moment that best fits a set of criteria. This guide builds
that workflow end to end across timezone conversion, candidate scoring, and SVG
rendering:

```text
location + local time window
    → caelus-birth    resolve the IANA zone and convert local bounds → UT (DST-safe)
    → caelus          rankMoments scans the window with custom electional rules
    → caelus-wheel    render the top-scoring chart as an SSR-safe SVG wheel
```

Because `rankMoments` takes an arbitrary user-defined scoring callback over
pure planetary calculations with zero I/O, the identical search runs in
browsers, server components, or Web Workers.

## Defining a scoring function

A scoring callback maps each candidate timestamp to a numeric score (higher
scores rank first). The sample rule below rewards an applying Moon–Venus trine,
penalizes a void-of-course Moon or combust Venus, and adds weight during
benefic planetary hours using built-in helpers:

<CodeBlock
  lang="typescript"
  label="score.ts"
  code={`import { Engine, aspectBetween, solarPhase, voidOfCourse, planetaryHour } from "caelus";

export function electionalScore(
  engine: Engine, jd: number, lat: number, lon: number,
): number {
  let score = 0;

  // A Moon-Venus trine is what we are hunting for. An applying aspect (still
  // tightening) counts for more than one that has already separated.
  const trine = aspectBetween(engine, "moon", "venus", jd);
  if (trine?.aspect === "trine") {
    score += trine.phase === "applying" ? 3 : 1;
  }

  // A void-of-course Moon is the classic "nothing comes of it" warning.
  if (voidOfCourse(engine, jd).isVoid) {
    score -= 4;
  }

  // A benefic burned by the Sun loses its strength. Cazimi, the exact heart of
  // the Sun, is the one nearness that helps rather than harms.
  const venus = solarPhase(engine, "venus", jd);
  if (venus === "combust" || venus === "under_beams") score -= 2;
  if (venus === "cazimi") score += 1;

  // Tilt toward hours ruled by the benefics.
  const hour = planetaryHour(engine, jd, lat, lon);
  if (hour && (hour.ruler === "venus" || hour.ruler === "jupiter")) {
    score += 1;
  }

  return score;
}`}
/>

`aspectBetween` returns the tightest aspect within orb (or `null`), tagged
`applying`, `separating`, or `exact`. `solarPhase` classifies solar proximity
as `cazimi`, `combust`, `under_beams`, or `null`. `voidOfCourse` detects whether
the Moon makes any further major aspects before changing sign, and
`planetaryHour` returns the Chaldean ruler of the current planetary hour at the
given coordinates.

## Running the search component

Inside the React component, `toUT` resolves the IANA zone from coordinates and
converts local start/end boundaries into UT Julian Days so DST transitions are
handled automatically. `rankMoments` evaluates candidates across the span, and
`engine.chartAt` builds the winning chart directly from the returned Julian
Day:

<CodeBlock
  lang="tsx"
  label="FindAMoment.tsx"
  code={`import { Engine, rankMoments } from "caelus";
import { embeddedData } from "caelus/data-embedded";
import { toUT } from "caelus-birth";
import { ChartWheel } from "caelus-wheel";
import { electionalScore } from "./score";

// Build the engine once and reuse it (module scope, not per render).
const engine = new Engine(embeddedData);

// Brooklyn, NY. Longitude is EAST-positive, so the Americas are negative.
const place = { lat: 40.69, lon: -73.99 };

// A local wall-clock window. toUT resolves the IANA zone from the coordinates
// and converts each end to UT.
const from = toUT({ year: 2026, month: 7, day: 1, hour: 0, minute: 0, ...place });
const until = toUT({ year: 2026, month: 7, day: 4, hour: 0, minute: 0, ...place });

export function FindAMoment() {
  // Sample every hour across the window and keep the single best instant.
  const [best] = rankMoments(
    { start: from.jdUt, end: until.jdUt, step: 1 / 24, limit: 1 },
    (jd) => electionalScore(engine, jd, place.lat, place.lon),
  );

  // rankMoments returns UT Julian Days, so build the winner's chart straight
  // from its JD with chartAt -- no calendar round-trip.
  const chart = engine.chartAt(best.jd, place.lat, place.lon, "placidus");

  return (
    <figure>
      <ChartWheel chart={chart} size={520} showAspects />
      <figcaption>{from.zone} · score {best.score}</figcaption>
    </figure>
  );
}`}
/>

## Scaling larger searches

A 72-hour hourly scan evaluates synchronously in a few milliseconds. For multi-week
client-side searches where blocking the UI thread would cause frame drops, use
`rankMomentsAsync`, which yields back to the browser event loop after every
batch of samples:

<CodeBlock
  lang="typescript"
  label="async.ts"
  code={`import { rankMomentsAsync } from "caelus";

const best = await rankMomentsAsync(
  { start: from.jdUt, end: until.jdUt, step: 1 / 24, limit: 5 },
  (jd) => electionalScore(engine, jd, place.lat, place.lon),
  256, // yield every 256 samples
);`}
/>

Because `caelus` performs no DOM or I/O calls, the same scan and scoring logic
also run inside a Web Worker.
