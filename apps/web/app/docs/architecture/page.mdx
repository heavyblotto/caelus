# Architecture

The Caelus packages form a layered pipeline rather than competing options. A
typical application passes birth data sequentially through the packages, with
each step handing plain structured objects to the next:

```text
location + local time
    → caelus-birth    resolve IANA zone from coordinates, local → UT (DST-safe)
    → caelus          positions, houses, aspects from the UT timestamp
    → caelus-wheel    SSR-safe SVG wheel from the chart object
    → caelus-mcp      (optional) expose the engine as MCP tools for AI clients
```

Only `caelus-birth` bundles external data (offline timezone boundaries and tzdb
rules). Because `caelus` stays I/O-free with zero runtime dependencies and
`caelus-wheel` outputs plain SVG markup, the same calculation and rendering code
runs in browsers, edge workers, Node.js servers, and MCP hosts.

## End-to-end example component

Here is the complete pipeline inside a single React server component, taking
local wall-clock birth details and rendering an SVG wheel with timezone
resolution built in:

<CodeBlock
  lang="tsx"
  label="NatalWheel.tsx"
  code={`import { Engine } from "caelus";
import { embeddedData } from "caelus/data-embedded";
import { localToChart } from "caelus-birth";
import { ChartWheel } from "caelus-wheel";

// Build the engine once and reuse it (module scope, not per render).
const engine = new Engine(embeddedData);

export function NatalWheel() {
  // Local wall-clock time and place, exactly as a person would enter them:
  const { chart, zone, status } = localToChart(
    { year: 1990, month: 6, day: 10, hour: 14, minute: 30, lat: 27.95, lon: -82.46 },
    engine,
  );

  return (
    <figure>
      <ChartWheel chart={chart} size={520} showAspects />
      <figcaption>
        {zone}
        {status !== "ok" && \` · \${status} local time — check the offset\`}
      </figcaption>
    </figure>
  );
}`}
/>

`localToChart` resolves the IANA timezone from latitude and longitude, converts
local time to UT, and runs `engine.chart`. It also returns a `status` flag
(`ok`, `ambiguous`, or `nonexistent`) so daylight saving ambiguities surface
explicitly rather than producing silent chart errors. See{" "}
<a href="/docs/edge-cases">Edge Cases &amp; Stability</a> for details on DST
handling.

## Package responsibilities

| Layer | Package | Input and output | Runtime deps |
| --- | --- | --- | :---: |
| Time & location | `caelus-birth` | local time + coordinates to UT + zone + status | tz data |
| Core engine | `caelus` | UT timestamp + coordinates to `Chart` object | none |
| Rendering | `caelus-wheel` | `Chart` object to SVG markup | none |
| AI tools | `caelus-mcp` | MCP tool call to structured chart payload | MCP SDK |
