# Common Tasks

Short code examples covering common chart calculations: house placements,
dignities, aspect patterns, planetary stations, sign ingresses, and local time
conversion. Every function returns structured JSON with no built-in narrative
interpretation. See <a href="/docs/charts">Computing Charts</a> for core options,
or jump to <a href="#for-agents-over-mcp">For agents</a> to use these tools
over MCP.

All snippets below assume an initialized `Engine`:

<CodeBlock
  lang="typescript"
  label="setup.ts"
  code={`import { Engine, julianDay } from "caelus";
import { embeddedData } from "caelus/data-embedded";

const engine = new Engine(embeddedData);
const jd = julianDay(2026, 6, 14); // a Julian Day (UT) to work from`}
/>

High-precision event searches (stations, ingresses, rise/set) typically run
best with the Node data loader; see <a href="/docs/data-tiers">Data Tiers</a>.

## Cast a natal chart

`engine.chart()` takes UT calendar fields and geographic coordinates, returning
every body (annotated with its house and essential dignities), the chart angles,
twelve house cusps, and all in-orb aspects:

<CodeBlock
  lang="typescript"
  label="natal.ts"
  code={`// 1990-06-10 14:30 UT, Tampa FL (27.95 N, 82.46 W), Placidus houses
const chart = engine.chart(1990, 6, 10, 14, 30, 0, 27.95, -82.46, "placidus");

chart.bodies.sun.lon;   // ecliptic longitude, degrees
chart.angles.asc;       // Ascendant, degrees
chart.cusps;            // [house 1, ..., house 12], degrees
chart.aspects.length;   // aspects within the active orbs`}
/>

## Read a body's house placement

Every body entry already carries its 1-based house number so you do not need to
compare longitudes against `chart.cusps` manually:

<CodeBlock
  lang="typescript"
  label="house.ts"
  code={`const chart = engine.chart(1990, 6, 10, 14, 30, 0, 27.95, -82.46, "placidus");

chart.bodies.mars.house;   // e.g. 7
chart.bodies.moon.sign;    // e.g. "Cancer"`}
/>

## Check essential dignities

Each body in a chart lists any sign-based essential dignities (`domicile`,
`exaltation`, `detriment`, `fall`). Call the standalone `dignities()` helper to
check any planet-and-sign pair without building a full chart:

<CodeBlock
  lang="typescript"
  label="dignities.ts"
  code={`import { dignities } from "caelus";

const chart = engine.chart(1990, 6, 10, 14, 30, 0, 27.95, -82.46, "placidus");
chart.bodies.venus.dignities;  // e.g. ["domicile"]

dignities("mars", "Aries");    // ["domicile"]
dignities("sun", "Libra");     // ["fall"]`}
/>

## Score traditional essential dignities

`dignityScore()` evaluates all five traditional dignities using Lilly's point
weights (rulership +5, exaltation +4, triplicity +3, term +2, face +1,
detriment −5, fall −4) for a degree and chart sect (`"day"` or `"night"`).
`almuten()` identifies the planet holding the highest score at a given degree:

<CodeBlock
  lang="typescript"
  label="dignity-score.ts"
  code={`import { dignityScore, almuten } from "caelus";

dignityScore("venus", 32, "day"); // 2 Taurus, day
// { rulership: 5, triplicity: 3, term: 2, total: 10, peregrine: false, ... }

almuten(5, "day"); // ruler of 5 Aries by day -> { planet: "sun", score: 7 }`}
/>

## List chart aspects

`chart.aspects` contains all active aspects between bodies, including both body
identifiers, the aspect type, phase (`applying`, `separating`, or `exact`),
strength, and orb from exact:

<CodeBlock
  lang="typescript"
  label="aspects.ts"
  code={`const chart = engine.chart(1990, 6, 10, 14, 30, 0, 27.95, -82.46, "placidus");

chart.aspects;
// [{ a: "sun", b: "moon", aspect: "trine", orb: 2.13 }, ...]`}
/>

## Detect aspect patterns

`detectPatterns()` identifies classical chart configurations (T-squares, grand
trines, grand crosses, yods, kites, mystic rectangles, and stelliums by sign and
house). Reported patterns are maximal, so a grand cross suppresses its nested
T-squares. Default orbs match the engine (plus quincunxes for yods) and can be
overridden:

<CodeBlock
  lang="typescript"
  label="patterns.ts"
  code={`import { detectPatterns } from "caelus";

const chart = engine.chart(1990, 6, 10, 14, 30, 0, 27.95, -82.46, "placidus");

detectPatterns(chart);
// [{ kind: "mystic_rectangle", bodies: ["chiron","moon","pluto","venus"], orb: 2.54 }, ...]`}
/>

## Compute a chart signature

`chartSignature()` aggregates element, modality, angularity, quadrant, and
hemisphere counts alongside the dominant element, modality, and sign and the
classical chart ruler:

<CodeBlock
  lang="typescript"
  label="signature.ts"
  code={`import { chartSignature } from "caelus";

const chart = engine.chart(1990, 6, 10, 14, 30, 0, 27.95, -82.46, "placidus");

const sig = chartSignature(chart);
sig.elements;   // { fire: 1, earth: 6, air: 1, water: 3 }
sig.dominant;   // { element: "earth", modality: "cardinal", sign: "Capricorn" }
sig.ruler;      // "sun" (ruler of the Ascendant's sign)`}
/>

## Find planetary stations

`stations()` returns every retrograde and direct station within a time window
as `[jd, direction]` pairs:

<CodeBlock
  lang="typescript"
  label="stations.ts"
  code={`import { stations } from "caelus";

stations(engine, "mercury", jd, jd + 365);
// [[2461190.4, "retrograde"], [2461214.1, "direct"], ...]`}
/>

## Find sign ingresses

Because each sign begins at a multiple of 30°, a sign ingress corresponds to a
longitude crossing. `crossings()` returns every Julian Day inside the window when
a body reaches the target longitude:

<CodeBlock
  lang="typescript"
  label="ingress.ts"
  code={`import { crossings } from "caelus";

// Mars entering Gemini (60 degrees), within the next ~2 years
const [next] = crossings(engine, "mars", 60, jd, jd + 800);`}
/>

## List lunar phases

<CodeBlock
  lang="typescript"
  label="phases.ts"
  code={`import { lunarPhases } from "caelus";

lunarPhases(engine, jd, jd + 90);
// [[jd, "new"], [jd, "first_quarter"], [jd, "full"], ...]`}
/>

## Find transits to a natal chart

`when()` evaluates boolean sky predicates over a time span. To find transits
to a natal placement, pass the natal body's longitude into `aspect()` and scan a
window; each match returns a `[jdStart, jdEnd]` interval while the aspect holds
within orb:

<CodeBlock
  lang="typescript"
  label="transits.ts"
  code={`import { when, aspect, julianDay } from "caelus";

const natal = engine.chart(1990, 6, 10, 14, 30, 0, 27.95, -82.46, "placidus");
const start = julianDay(2026, 1, 1);
const end = julianDay(2027, 1, 1);

// transiting Mars conjunct the natal Sun, within 1 degree of exact
const windows = when(engine, aspect("mars", "conjunction", natal.bodies.sun.lon), start, end);
windows[0]; // [jdStart, jdEnd] of the first pass`}
/>

## Find sunrise and sunset

`riseSet()` returns the Julian Day of the next horizon or meridian event after
`jd`, or `null` if none occurs (such as during polar day or night):

<CodeBlock
  lang="typescript"
  label="riseset.ts"
  code={`import { riseSet } from "caelus";

// next sunrise and sunset over Tampa (27.95 N, 82.46 W) after jd
const sunrise = riseSet(engine, "sun", jd, 27.95, -82.46, "rise");
const sunset = riseSet(engine, "sun", jd, 27.95, -82.46, "set");`}
/>

## Compute parans (co-angular bodies)

`parans()` finds pairs of bodies that simultaneously cross the horizon or
meridian at a given latitude within a specified time tolerance (default 30
minutes). Because diurnal arcs depend only on declination and latitude, no
longitude is required:

<CodeBlock
  lang="typescript"
  label="parans.ts"
  code={`import { parans } from "caelus";

parans(engine, jd, 27.95); // 30-minute window by default
// [{ a: "jupiter", a_angle: "rise", b: "mars", b_angle: "mtransit", gap_min: 20, ... }, ...]`}
/>

## Compute a solar return chart

`solarReturn()` finds the Julian Days within a search range when the Sun returns
to its natal longitude. Pass the returned timestamp into `engine.chartAt()` to
cast the return chart:

<CodeBlock
  lang="typescript"
  label="return.ts"
  code={`import { solarReturn, julianDay } from "caelus";

const natalJd = julianDay(1990, 6, 10, 14, 30, 0);
const [returnJd] = solarReturn(engine, natalJd, jd, jd + 366);
const returnChart = engine.chartAt(returnJd, 27.95, -82.46, "placidus");`}
/>

## Convert local birth times safely

Because `caelus` operates in Universal Time, passing local wall-clock time
directly introduces multi-hour errors in house cusps and angles. Use
`caelus-birth` to resolve the IANA zone offline from latitude/longitude and
convert historical daylight saving rules into UT:

<CodeBlock
  lang="typescript"
  label="birth.ts"
  code={`import { localToChart } from "caelus-birth";

// born 1988-02-14 08:15 local in London
const { chart, utc, zone } = localToChart(
  { year: 1988, month: 2, day: 14, hour: 8, minute: 15, lat: 51.5, lon: -0.12 },
  engine,
  "placidus",
);
chart.angles.asc; // computed from the correct UT instant`}
/>

## Check Vedic nakshatra and dasha periods

Caelus supports sidereal zodiacs directly. Request the Moon's longitude in a
sidereal ayanamsa (such as `"sidereal:lahiri"`), pass it to `nakshatra()`, and
compute the active Vimshottari period with `vimshottariActive()`. See{" "}
<a href="/docs/vedic">Vedic &amp; Jyotish</a> for divisional vargas, alternative
dashas, and planetary yogas:

<CodeBlock
  lang="typescript"
  label="vedic.ts"
  code={`import { nakshatra, vimshottariActive, julianDay } from "caelus";

const birthJd = julianDay(1990, 6, 10, 14, 30, 0);
const moonLon = engine.longitude("moon", birthJd, { zodiac: "sidereal:lahiri" });

nakshatra(moonLon);                       // { name, pada, lord, ... }
vimshottariActive(moonLon, birthJd, jd);  // { maha, antar, pratyantar } for "now"`}
/>

## For agents over MCP

The same calculations are available as MCP tools returning structured,
interpretation-free JSON so AI clients can handle reasoning and narrative
generation cleanly. After connecting an MCP client (see{" "}
<a href="/docs/mcp">MCP Setup</a>), key tools include:

- **`natal_chart`** / **`current_sky`**: complete charts with body positions, houses, dignities, angles, cusps, and aspects.
- **`transits`**: transiting positions and active aspects relative to a natal chart.
- **`find_aspect_dates`**: timestamps when a specified planetary aspect reaches exactness in a date window.
- **`sky_events`**: planetary stations, sign ingresses, lunar phases, and rise/set times.
- **`synastry`** / **`composite`**: inter-chart aspects and midpoint/composite charts.
- **`dignities`**, **`void_of_course`**, **`planetary_hours`**, **`returns`**, **`progressions`**: traditional Hellenistic and timing helpers.
- **`aspect_patterns`** / **`chart_signature`**: named aspect configurations (T-squares, grand trines, yods, stelliums) and element/modality/quadrant summaries with chart ruler.
- **`similar_skies`**, **`electional_search`**, **`cosmic_weather`**: historical sky similarity scans, electional window ranking, and daily planetary summaries.
- **`parans`**: co-angular body pairs (simultaneously rising, culminating, setting, or anti-culminating) at a latitude.
- **`output: "canonical"`** on chart, return, and parans tools: quantized integer payloads paired with a SHA-256 digest for deterministic cross-runtime hashing and caching, with signs, houses, and aspects derived from the quantized integers so facts stay self-consistent. Adding `remainders` returns an integer residue sidecar that reconstructs finer grid steps accurately and flags rounding-boundary sensitivity.

Full tool definitions and schemas are documented in{" "}
<a href="/docs/mcp">MCP Setup</a>.
