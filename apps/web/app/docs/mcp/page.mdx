# MCP Setup

`caelus-mcp` exposes the calculation engine over the Model Context Protocol.
Because AI assistants call deterministic ephemeris tools on every turn rather
than estimating positions from memory, charts and timing windows remain exact.

You can connect to the same **thirty-eight** tools via either transport:

- **Hosted (Streamable HTTP)**: point your MCP client at
  `https://www.ephemengine.com/api/mcp` with no local installation.
- **Local (stdio)**: run `npx -y caelus-mcp` locally for offline use, strict
  version pinning, or extended pre-1000 CE data packs.

## Hosted endpoint (no install)

All tools run statelessly over MCP Streamable HTTP at
`https://www.ephemengine.com/api/mcp`. Every request is self-contained with zero
session state to maintain, and planetary positions match the stdio server across
modern dates (1000–3000 CE).

<Tabs>
  <Tab label="Cursor">

Add the entry below to `.cursor/mcp.json` (project) or `~/.cursor/mcp.json`
(user-wide), then reload Cursor:

<CodeBlock
  lang="json"
  label=".cursor/mcp.json"
  code={`{
  "mcpServers": {
    "caelus": {
      "url": "https://www.ephemengine.com/api/mcp"
    }
  }
}`}
/>

  </Tab>
  <Tab label="Claude Code">

Register the remote MCP endpoint from the CLI:

<CodeBlock
  lang="bash"
  label="Terminal"
  code={`claude mcp add --transport http caelus https://www.ephemengine.com/api/mcp`}
/>

  </Tab>
  <Tab label="VS Code">

Create `.vscode/mcp.json`. VS Code uses the top-level `servers` key alongside an
explicit `"type": "http"`:

<CodeBlock
  lang="json"
  label=".vscode/mcp.json"
  code={`{
  "servers": {
    "caelus": {
      "type": "http",
      "url": "https://www.ephemengine.com/api/mcp"
    }
  }
}`}
/>

  </Tab>
  <Tab label="curl">

The HTTP endpoint speaks JSON-RPC 2.0 and accepts direct `tools/call` requests
without requiring an explicit initialization handshake:

<CodeBlock
  lang="bash"
  label="Terminal"
  code={`curl -s https://www.ephemengine.com/api/mcp \\
  -H 'Content-Type: application/json' \\
  -H 'Accept: application/json, text/event-stream' \\
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call",
       "params":{"name":"natal_chart",
                 "arguments":{"date":"1990-06-10T14:30:00Z","lat":27.95,"lon":-82.46}}}'`}
/>

Issuing a `GET` request returns a JSON descriptor listing all available tools,
resources, and prompts so you can verify connectivity.

## Running locally via stdio

To run the local server straight from npm with no global install:

<CodeBlock lang="bash" label="Terminal" code={`npx -y caelus-mcp`} />

Because `caelus-mcp` communicates over stdin/stdout JSON-RPC, running it
directly in an interactive shell simply waits for input. Configure one of the
clients below to spawn and manage it automatically.

## Available tools

Once connected, your MCP client should display all **thirty-eight tools** in its
tool panel:

**Charts and readings**

- `natal_chart`: natal positions, house cusps, and aspects.
- `current_sky`: planetary positions for any timestamp with optional location.
- `transits`: transiting planets and aspects to a natal chart across a window.
- `synastry`: inter-chart aspects, house overlays, composite atoms, and a prompt brief.
- `composite`: midpoint composite and Davison relationship charts.
- `returns`: solar and lunar return timestamps paired with return charts.
- `progressions`: secondary progressions and solar-arc directions.
- `counterfactual_chart`: perturbs a birth chart (shifting time, coordinates, or body longitudes) and diffs sign, house, and aspect changes.

**Sky events, geometry, and historical search**

- `sky_view`: frames the visible sky from an observer's location as pixel coordinates and an AI image-generation prompt (including brightness, Moon phase orientation, twilight, Milky Way band, deep star field, and coordinate overlays).
- `sky_view_sequence`: generates a frame sequence across time for sky animation.
- `sky_events`: computes rising/setting times, lunar phases, stations, zodiac crossings, solar/lunar eclipses, central eclipse coordinates, path widths, and local contact circumstances.
- `parans`: finds co-angular planet pairs crossing horizon or meridian lines within a 24-hour window at a given latitude.
- `find_aspect_dates`: searches when a specified aspect reaches exactness inside a date window.
- `electional_search`: ranks timestamps inside a window by desired aspects while optionally avoiding a void-of-course Moon.
- `cosmic_weather`: summarizes active configurations, planetary stations, and void-of-course periods for a given date.
- `similar_skies`: ranks timestamps within a date range by cosine similarity to a target chart.
- `date_sky`: searches multi-year or multi-millennium spans for matching planetary positions (used for dating historical horoscopes).
- `chart_stability`: reports which chart facts remain invariant across a time uncertainty window and when changing facts transition.
- `heliacal`: computes first and last visibility dates from a location for planets, catalog stars, or the Moon (heliacal risings and settings, evening and morning apparitions of Mercury and Venus, and new and old crescents), including earliest and latest dates across clear and hazy atmospheric bounds.

**Hellenistic time-lords**

- `profections`: annual and monthly profections with lords of the year.
- `firdaria`: Persian planetary time-lord periods.
- `releasing`: zodiacal releasing (aphesis) from Fortune or Spirit.
- `directions`: primary directions to chart angles and optional mundane directions between planets.
- `lots`: the seven sect-aware Hermetic lots.

**Vedic (Jyotish)**

- `nakshatras`: lunar mansions, padas, and dasha lords.
- `dasha`: Vimshottari, Yogini, and Ashtottari dasha timelines.
- `vargas`: Parashari divisional charts.
- `yogas`: Pancha Mahapurusha, raja/dhana yogas, and chart yogakarakas.

**Analysis, dignities, and structured facts**

- `dignities`: essential dignities and sect status for the seven traditional planets.
- `planetary_hours`: active Chaldean planetary hour and daily sequence.
- `void_of_course`: void-of-course Moon timing windows.
- `rectification_grid`: candidate ASC/MC sweeps over a grid of birth times.
- `aspect_patterns`: maximal classical configurations (T-squares, grand trines, grand crosses, yods, kites, mystic rectangles, and stelliums).
- `chart_signature`: elemental, modal, quadrant, and hemisphere counts alongside dominant indicators and chart ruler.
- `chart_facts`: projects validated chart placements into ranked, citable fact atoms and a formatted prompt brief, accepting `when` provenance anchors, an inline `anchors` registry, `realm`, `target_date`, `include_vedic`, and `constraints` (see [Interpretation](/docs/interpretation) and [Provenance](/docs/provenance)).

**Synthetic worlds**

- `synthetic_validate`: checks custom synthetic orbital definitions for invalid eccentricities, duplicate IDs, non-positive periods, or missing observers.
- `synthetic_positions`: returns longitudes, speeds, and retrograde flags for all bodies in a synthetic system.
- `synthetic_sky_view`: frames a combined real/synthetic sky view with authored magnitudes, colors, and angular radii.

`natal_chart` and `current_sky` also annotate solar proximity (`cazimi`,
`combust`, `under_beams`) and aspect phase (`applying`, `separating`,
`exact`) with normalized strength.

Alongside these thirty-eight tools, the server exposes three **resources**
(`caelus://glossary`, `caelus://accuracy`, and `ui://widget/chart.html`) and
two **prompts** (`rectification_session` and `natal_reading`).

## Troubleshooting

- **`npx` fails to launch from GUI apps**: Desktop apps (Claude Desktop,
  Cursor) often omit shell `PATH` additions from `nvm` or Homebrew. Set
  `command` to the full executable path reported by `which npx` (requires Node
  18+).
- **Tools do not appear**: Most clients read MCP config files only at startup.
  Fully quit and reopen the application, and validate JSON syntax for trailing
  commas.
- **Cold-start delay**: Running `npx -y` without a pinned version checks npm on
  first launch before caching. Pin a release version below to keep startup fast
  and predictable.

## Pinning a production version

`npx -y caelus-mcp` resolves `latest` by default. Pin a matching release version
across all packages for reproducible behavior:

<CodeBlock
  lang="json"
  label="pinned"
  code={`{
  "mcpServers": {
    "caelus": {
      "command": "npx",
      "args": ["-y", "caelus-mcp@0.15.0"]
    }
  }
}`}
/>
